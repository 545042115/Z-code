## Purpose

帮助用户选择正确的支付宝支付产品并完成集成。覆盖 8+ 主流支付场景，避免选错方案导致返工。

## Use When

用户提到以下任一场景时使用此 Skill：
- "接入支付宝" / "集成支付宝支付" / "对接支付" / "支付宝收款"
- "加个支付功能" / "支付宝下单"
- "H5 支付" / "小程序支付" / "App 支付" / "网页支付" / "PC 支付" / "付款码" / "扫码支付"
- "预授权" / "周期扣款" / "自动续费" / "会员订阅" / "连续包月" / "代扣" / "商家扣款"

**不适用场景**：微信支付、银联支付、支付宝转账、对账、红包等非收单场景。

## Workflow

### 步骤 1：识别用户场景

根据用户描述判断属于哪种支付场景：

| 场景 | 推荐产品 |
|------|---------|
| 线下面对面付款 | 当面付（offline_trade） |
| 用户打开 App 内的 H5 页面支付 | 手机网站支付（wap） |
| 商家在 PC 网站展示二维码，用户扫码 | 电脑网站支付（pc） |
| 用户在原生 App 中支付 | App 支付（app） |
| 用户在微信/支付宝小程序内支付 | 小程序支付（mini_program） |
| 周期扣款、会员订阅、连续包月 | 商家扣款（商家代扣 / 周期付） |
| 押金、租赁等需要冻结额度 | 预授权支付（pre_auth） |

### 步骤 2：询问关键信息

- 应用类型（移动 App / 网站 / 小程序 / 线下）
- 资金流向（一次性 / 周期）
- 是否需要退款

### 步骤 3：给出选型建议 + 集成步骤

## Do

- 先问清楚用户场景（线下 / H5 / App / 小程序）再推荐
- 推荐同时提供 SDK 和 OpenAPI 两种集成方式
- 提醒用户申请商家号 + 配置公私钥
- 强调生产环境必须用签名 + 验签
- 给出参考链接：https://opendocs.alipay.com

## Do Not

- 不要把微信支付、银联支付混入此方案
- 不要在生产用 sandbox 网关
- 不要在用户未确认场景前直接给代码
- 不要忽略退款流程（支付必有退款）

## Examples

### 场景 1：用户说"我要做一个小程序商城"

→ 选型：小程序支付（mini_program）+ 电脑网站支付（pc）双端
→ 步骤：
  1. 注册支付宝商家账号
  2. 创建小程序应用
  3. 申请小程序支付产品
  4. 配置 RSA2 密钥
  5. 集成小程序支付 SDK：`alipay.trade.create`
  6. 后端接收回调验签
  7. 实现退款接口

### 场景 2：用户说"我做一个健身房会员订阅，每月自动扣费"

→ 选型：商家扣款（period_pay / 周期付）
→ 步骤：
  1. 申请"周期付"产品
  2. 第一次支付走 `alipay.trade.app_pay` 或当面付签约
  3. 后续周期扣款走 `alipay.trade.pay`
  4. 签约协议号需用户授权确认
  5. 失败重试 + 通知用户

## Verification

向用户确认所推荐方案是否符合场景，给出集成代码框架。
