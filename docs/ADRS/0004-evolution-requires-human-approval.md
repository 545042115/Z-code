# 0004. Evolution 阶段所有变更需人工确认

- 状态：Accepted
- 日期：2026-06-17
- 决策人：@Ziner V2 架构组
- 影响阶段：Phase 5

## 背景

Self-Evolution 层有自动改 Prompt / Tool / Skill 的诱惑。
直接在线上自动改写会引发：
- 不可回滚的体验退化
- 安全风险（Prompt 注入放大）
- 难以归因的责任链

## 备选方案

- 方案 A：完全自动演化（无人工介入）
- 方案 B：完全人工（系统只给建议）
- 方案 C：建议 + Diff + 一键确认（默认人工，可选自动）

## 决策

采用 **方案 C 的最严子集**：

- Evolution 引擎**只生成候选版本**（Prompt / Tool / Skill diff）
- **所有候选默认处于 `Proposed` 状态**，不进入生产
- 候选需在 UI 上展示 diff、性能预测、A/B 历史
- **必须由人类点击"应用"或"驳回"** 才会落地
- 落地后进入"灰度观察期"（默认 24h），期间异常指标自动回滚

> 即便后续加入"自动应用"开关，默认关闭，且需二次确认。

## 后果

### 正面
- 退化与安全风险被人类兜住
- 决策有据可依（Diff + 历史指标）
- 出问题可一键回滚

### 负面 / 成本
- 流程较慢，无法"全自动进化"
- 需要 UI 与告警基础设施配合

### 缓解措施
- 候选数量限制（同时最多 5 个待确认）
- 高信心度候选（连续 N 次 A/B 显著胜出）可标记"推荐应用"
- 灰度期异常自动回滚由 Phase 4 指标 + Phase 5 控制器共同实现
